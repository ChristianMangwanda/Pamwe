# design-sync notes for Pamwe

Target project: "Pamwe Design System" (`5163ca4a-d2ce-4f9a-999a-4be76903e06e`), created 2026-07-12.

- This repo is an Expo/React Native APP, not a web component library. There is no
  Storybook anywhere (zero `@storybook/*` deps, zero `*.stories.*` files) and no
  library build. The synced surface is `src/components/ui/*` + ThemeProvider +
  tokens/typography, pre-bundled for the web by `.design-sync/web/prebundle.mjs`
  (react-native → react-native-web, Metro-style `.web.js` resolution replicated
  with an esbuild plugin). The converter consumes
  `.design-sync/.cache/web-dist/` as if it were a normal package dist.
- Faithful-install step: node_modules was already present and healthy (active dev
  repo, npm, node 24); `npm ci` was skipped to avoid blowing away a working dev
  env. If a future sync runs on a fresh clone: `npm ci` (postinstall applies
  patch-package patches).
- `.design-sync/node_modules` is a symlink to `../.ds-sync/node_modules` so
  `web/prebundle.mjs` can resolve esbuild. Gitignored; recreate on fresh clones:
  `ln -sfn ../.ds-sync/node_modules .design-sync/node_modules` (after staging
  `.ds-sync/` per the skill).
- Web shims (all in `.design-sync/web/shims/`):
  - `expo-glass-effect` is iOS-only; the shim forces `isLiquidGlassAvailable()`
    to false so `Glass` renders its real BlurView branch (expo-blur works on web).
  - `src/lib/supabase` is replaced by a throwing proxy: CategoryChip → lib/prayers
    imports the client module, whose real version boots createClient() at load.
  - `src/components/PamweFab` is replaced by a stub exporting `FAB_CLEARANCE = 96`
    (Screen needs only the constant; the real module drags in expo-router).
    RE-SYNC RISK: if FAB_CLEARANCE changes in the app, update the shim.
- Font family names must be the exact RN names (`Fraunces_600SemiBold` etc.) —
  `web/fonts.css` maps all 10 families from src/constants/typography.ts to the
  TTFs inside the `@expo-google-fonts` packages.
- `tokens.css` is GENERATED by prebundle.mjs from src/theme/tokens.ts (light +
  dark + swatches + gutter). Never hand-edit it; edit tokens.ts.
- Component CSS is runtime-injected by react-native-web, so `[CSS_RUNTIME]` from
  validate is expected and correct for this repo.

## Preview-authoring facts (folded from wave 1, 2026-07-12)

- Avatar: fixed 80px column; `status` strings longer than ~9 chars wrap. One short word.
- SegmentedControl: segments are `{ key, label }` (not value/label); `value` + `onChange(key)`.
- Switch: no disabled prop; off-track is hardcoded `#C9B99B`, on-track `colors.accent`.
- ProgressBar: `progress` 0..1 clamped internally; track renders visibly at 0.
- Spinner: reanimated rotation freezes at an arbitrary angle in static captures. Expected,
  not a bug (known render warn).
- Surfaces (Card/Glass/StripedBanner): cream-on-white is near invisible; wrap preview cells
  in an app-bg shell (`#EFE6D6`, padding 20, radius 18). Glass needs detail behind it to read.
- StripedBanner: children want absolute positioning; curated tints map per
  src/lib/planArtwork.ts (amber John, sky Psalms, rose Cord, sage M'Cheyne; default line2).
- BottomSheet: `cfg.overrides` changes that include `viewport` alter the graded config slice:
  scoped preview-rebuild then fails `[CONFIG_STALE]` until a full package-build re-stamps.
  Config override edits are orchestrator work BEFORE waves, or budget a full rebuild after.
- Screen: fixed DOM frame (390x600, overflow hidden, display flex) + `animated={false}`;
  interleave plain div spacers (its gutter View has no gap). Web safe-area insets are 0.
- Floral: renders 0x0 without explicit width/height. App sizes: corner 116/96, divider ~140x26.
- TwineDivider: 10px tall, sub-pixel strokes; compose between text/avatars or it reads empty.
  It still imports the frozen legacy `constants/colors` palette, so it does not theme in dark
  mode (app-code fact worth surfacing, not a sync bug).
- Previews are light-mode only: never call setMode (persists to localStorage and would bleed
  into every other preview). Dark rendering is unverified in v1.
- playwright@1.60.0 is pinned in .ds-sync to match the cached chromium build 1223.

## Known render warns

- `[RENDER_THIN]` on BottomSheet: the open sheet anchors to the card bottom over the scrim,
  so the mounted-text heuristic reads it as thin. The graded capture (both cells) is complete
  and correct; triaged legitimate 2026-07-12.
- Spinner freezes at an arbitrary rotation angle in captures (reanimated); legitimate.

## Re-sync risks

- `FAB_CLEARANCE` is duplicated in `web/shims/PamweFab.tsx` (see above).
- The pre-bundle inlines react-native-web, reanimated, react-native-svg,
  expo-blur, safe-area-context: major version bumps of any of these can change
  web rendering; re-verify previews after such bumps rather than trusting grades.
- Native-only components (VoiceRecorder, AudioPlayer) and app composites were
  deliberately left out of scope for the first sync (user chose UI kit + tokens).
